Cora Z7-10 · PetaLinux 2025.1

GNU Radio on embedded Zynq

A reproducible, field-tested path from a PS-only Cora baseline to a bootable ext4 SD image running a headless GNU Radio flowgraph over SSH.

Linux 6.12.10-xilinx GNU Radio 3.10.12 VOLK 3.2.0 Python 3.12 Static Ethernet Smoke test passed

1. What we achieved

Boot

U-Boot loads a Linux kernel and a persistent ext4 root filesystem from microSD partition 2.

GNU Radio

A headless ARMv7 build includes runtime, blocks, analog, digital, FFT, filter, network, Python, and VOLK.

Access

The board uses 192.168.10.2/24; the directly connected Ubuntu host uses 192.168.10.1/24.

Proof

A vector source, multiply block, and vector sink produced [2, 4, 6, 8] on the Cortex-A9.

This is the software baseline for later FPGA acceleration. GNU Radio Companion stays on the Ubuntu development host; the embedded image is deliberately headless to fit the Cora Z7-10's 512 MiB DDR.

4. Integrate GNU Radio

  1. Fetch the pinned layer

    meta-sdr is reproducibly fetched rather than vendored into Git.

    scripts/fetch-meta-sdr.sh

    The script checks out commit 563727209e5d8c7cdebc35157bab4dc07e8fb235, marks it Scarthgap-compatible, and disables its GUI-oriented default before BitBake parses the recipe.

  2. Apply the project configuration

    source scripts/activate-tools.sh
petalinux-config \
  --project software/petalinux/cora-z7-10-baseline \
  --silentconfig
petalinux-config \
  --project software/petalinux/cora-z7-10-baseline \
  --component rootfs \
  --silentconfig

    The project selects GNU Radio, the external layer, ext4 root-on-SD, OpenSSH, static networking, and stable eth0 naming.

  3. Understand the local recipe fixes

    gnuradio_%.bbappend enables the useful headless modules, adds the real python3-pyyaml runtime dependency, and sets the Git checkout directory explicitly. volk_%.bbappend removes two stale test-related patches and applies the same source-directory compatibility fix.

Why edit the fetched recipe? cmake_qt5 is inherited while the base recipe is parsed. Replacing PACKAGECONFIG later in a .bbappend does not remove that already-inherited dependency, so the fetch script changes the pinned checkout deterministically.

6. Write the microSD card

Recommended GUI

scripts/write-sd-image-gui

The helper only offers removable drives, verifies capacity, requires typing ERASE, unmounts partitions, and uses the normal desktop authorization prompt.

Command-line alternative

lsblk -p -o NAME,SIZE,MODEL,TRAN,MOUNTPOINTS
sudo umount /dev/sdX1 /dev/sdX2
sudo dd \
  if="$PWD/software/petalinux/cora-z7-10-baseline/images/linux/petalinux-sdimage.wic" \
  of=/dev/sdX bs=4M status=progress conv=fsync
sync

Destructive operation: replace /dev/sdX with the whole removable card, never a partition and never the Ubuntu system disk.

7. First boot

  1. Set the Cora boot-mode jumper for SD boot.
  2. Connect USB-UART and Ethernet, insert the card, then power on.
  3. Open the correct serial node at 115200 baud, 8N1.
picocom --baud 115200 /dev/ttyUSB1

The final kernel command line must contain:

root=/dev/mmcblk0p2 rootfstype=ext4 ro rootwait net.ifnames=0

mmcblk0p1 is the FAT boot partition; mmcblk0p2 is the persistent ext4 root filesystem.

If the console appears to pause after CAN device driver interface, wait. That line was merely the last visible message while later drivers initialized; the actual failing image continued and eventually printed the root-filesystem panic.

8. Ethernet and SSH

Configure the Ubuntu side

ip link
sudo ip address flush dev HOST_ETHERNET_INTERFACE
sudo ip address add 192.168.10.1/24 dev HOST_ETHERNET_INTERFACE
sudo ip link set HOST_ETHERNET_INTERFACE up
ping -c 3 192.168.10.2

Connect to the target

ssh petalinux@192.168.10.2

The bring-up credential used during validation was username petalinux, password root. Change it before using an untrusted network. The password for the petalinux account is not necessarily the root account's su password.

On the board, verify:

ip link show eth0
ip address show eth0
ip route
cat /sys/class/net/eth0/carrier

9. Run the GNU Radio smoke test

Copy the checked-in script rather than pasting a multiline heredoc into the serial terminal:

scp scripts/gnuradio-smoke-test.py petalinux@192.168.10.2:/tmp/
ssh petalinux@192.168.10.2 python3 /tmp/gnuradio-smoke-test.py

Expected result:

Result: [2.0, 4.0, 6.0, 8.0]
GNU Radio smoke test: PASS

The test constructs a vector source, multiplies every float by 2, captures the output, and asserts the exact result. It exercises Python bindings, the scheduler, gr-blocks, and VOLK without requiring FPGA hardware or a radio peripheral.

During validation, vmcircbuf emitted shared-memory warnings but the flowgraph completed and passed. Treat those warnings as a future performance/configuration item, not a failure of this basic functional test.

10. Hiccups we hit—and durable fixes

SymptomRoot causeDurable fix
Qt/GRC dependencies entered a headless target build.The base meta-sdr recipe inherited cmake_qt5 during parsing.The pinned fetch script changes the upstream default before parsing; the local append also keeps PACKAGECONFIG empty.
VOLK failed in do_patch.Two upstream ptest/compiler-flag patches no longer matched VOLK 3.2 and were irrelevant with tests disabled.Remove those patch URIs in volk_%.bbappend.
GNU Radio/VOLK source was not found during configuration.Scarthgap's Git fetch layout differed from the newer recipe's assumption.Set S = "${WORKDIR}/git" explicitly in both appends.
ModuleNotFoundError: No module named 'yaml'gr-blocks imports variable_save_restore.py, even in a headless build.Add python3-pyyaml to GNU Radio runtime dependencies.
module 'yaml' has no attribute 'SafeDumper'A placeholder/stub yaml module satisfied the import name but was not PyYAML.Remove the stub and install the real PyYAML package through the image recipe.
Shell showed > prompts or Python reported unexpected indent.Multiline heredocs were pasted with indentation/typos over serial.Copy and run scripts/gnuradio-smoke-test.py.
No such file or directory writing under /root.The session was the unprivileged petalinux user; /root was inaccessible or absent in its view.Use /tmp for the smoke test; root privileges are unnecessary.
Kernel panic mounting /dev/ram0.The device tree still carried initrd bootargs although the WIC contained a valid ext4 partition.Select EXT4 rootfs, set /dev/mmcblk0p2, rebuild boot artifacts, and rewrite the card.

RTNETLINK answers: Operation not permitted.The serial shell lacked network-administration privileges.Fix networking in the image, or use an authenticated administrative shell; do not rely on runtime commands as the permanent solution.

11. Inspect a bad boot in U-Boot

Press any key during the countdown to reach the Zynq> prompt. Confirm the ext4 root filesystem is present:

ext4ls mmc 0:2 /

A valid root partition shows directories such as bin, etc, lib, usr, and var. Inspect the loaded device tree:

fdt addr 0x00100000
fdt print /chosen

If it reports root=/dev/ram0, the boot metadata is wrong—not the ext4 filesystem.

Why the one-off fdt set did not stick: no FDT address was configured at the first prompt, and then boot executed boot.scr, which loaded its own kernel/device-tree flow. Correct the PetaLinux configuration and regenerate the card for a persistent fix.
